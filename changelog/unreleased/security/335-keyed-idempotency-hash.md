- **A request's password is no longer kept as a plain hash for retries.** When an app or script sends a request with an `Idempotency-Key`, the server keeps a hash of the request so it can tell a retry from a reused key. That hash was a plain SHA-256 of the whole body, so anyone holding only the database could test guesses of a mailbox password sent when connecting an IMAP mailbox (or a signup code, or a token) against it. It is now keyed with a key derived from `CAMPBOOKS_SECRET_KEY`, which the database never holds. A retry of a request first sent before the upgrade gets 422 `idempotency_key_reused` rather than running again; send it with a new key. The old hashes expire within about a day. Self-hosters running without `CAMPBOOKS_SECRET_KEY` see a startup warning: retries then replay only on the process that first ran them.
